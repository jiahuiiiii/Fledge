## Implementation and verification

`thesis-watch-relevance-8` requires an explicit source relationship: direct evidence, an argument actually made by the source, an inferred link, background, unclear or unrelated. Inferred links must use `possible_link`, identify a saved anchor and state the missing evidence. Code rejects incompatible combinations instead of silently rewriting them. Only the existing support/challenge/risk/answer relations count toward publication. Actual source arguments can still challenge an idea without being independently verified facts.

New schemas constrain each item to its own source, saved anchor and supplied parent. The question-only route remains `thesis-question-watch-2`; all four retained question requests and identities match byte-for-byte. No new model stage, provider, database migration, acquisition or watch activation is introduced. Existing saved results keep their old method and meaning. Installing the method does not re-alert previously seen text.

History, mixed alert details and private/periodic exports show the basis and missing evidence. Possible-only checks remain outside the Updates inbox. A mixed check can contain quiet context alongside one qualifying alert; the quiet item is explicitly labelled and excluded from the count. Source withdrawal withholds its text and evidence gap together.

The full isolated suite passes **906 backend cases**. A final **35-case focused run** overlaps that suite and adds one mixed-export regression. Fourteen frontend checks, the production build and the private-alert browser journey at 320, 390 and 1440 pixels pass. Browser fixtures are authored and make no source or paid request. These verify delivery, isolation, caching, escape/withdrawal behavior, history and presentation; they do not measure semantic accuracy.
