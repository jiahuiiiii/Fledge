# Phase 36 — conversation context in saved-idea alerts

This is a parent-authored review from five perspectives, not independent consultant signoff or participant evidence.

| Perspective | Finding | Implemented response and limit |
| --- | --- | --- |
| Product | Sentiment could use a reply's parent while private relevance still interpreted the reply alone. | Both now consume the same pinned parent. Parent-only opinions cannot establish the reply's connection to an idea. Real semantic performance is not yet measured. |
| Research | Later parent inspection could otherwise silently change the evidence behind an old alert. | Private preparation never fetches or attaches a new parent. Old sample/check content stays unchanged and earlier methods are disclosed. This still cannot establish historical thread wording. |
| Data/ML | Importing a parent's opinion as the reply's own argument could create a false support/challenge. | Require separate child-body and own-parent citations, complete source coverage, and explicit attribution instructions. Exact citations are necessary but do not prove the relation is correct. |
| Architecture | Context must remain private when combined with saved reasoning, and follow withdrawal through every derived view. | Reuse the analysis-access boundary, owner policies, immutable packets, shared ledger and export escaping. No new migration, provider, source or paid stage. |
| UX/business | A parent loaded later could look like new market evidence and manufacture attention. | Existing source-text deduplication keeps context-only watch changes quiet. Show parent evidence in Updates/History/downloads. Prospective alert usefulness and willingness to pay remain unvalidated. |
