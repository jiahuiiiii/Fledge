# Daily filing checks — phase 30

The architecture proposes daily fundamentals acquisition as well as periodic news/social checks. Previously only source aging and evaluation were automatic: acquiring SEC figures required **Refresh filings**. The optional **Start daily filing checks** control in Fundamentals closes that acquisition gap for the six supported companies. It is off by default and independent of paid news/social watches and saved-idea approval.

Enabling queues one immediate background check, then one check every 24 hours while the local app runs. An overdue schedule runs once after restart, with the next due time measured from that new attempt. The app does not replay missed days or make an immediate automatic retry after failure. Repeating the same enabled setting does not reschedule it. Stopping prevents future checks; already started shared-source retrieval may finish. No AI request or extra key is needed.

The existing SEC reader performs its fixed submissions/companyfacts requests using the configured contact identity, persisted global one-request-per-second clock, 15-minute company cooldown, two-minute source lease and existing response bounds. New supported numerical inputs enter immutable shared snapshots, then the existing worker reassesses approved definitions and publishes only meaningful changes in Updates. This checks supported annual/direct-quarter figures, not every 8-K, filing narrative, earnings release or announcement. Other financial statement rows can refresh without a numerical-condition alert. Reporting age remains tied to the period end, not retrieval time. A daily poll plus local downtime and source delay is not real-time detection.

Migration 22 adds private schedules and append-only attempt/result journals. Three-minute claims prevent competing local workers from duplicating a scheduled attempt. Owner-scoped settings/history use the restricted application role; the SEC collector retains its separate shared-source role and cannot read private watch tables. Result references must point to a matching successful SEC check within that attempt's time window. Late completion is unconfirmed and cannot overwrite a later claim. Original rows, definitions and journals remain immutable.

History distinguishes changed supported inputs, unchanged supported inputs, a recent shared attempt (no new request), failed checks, running checks and interrupted/unconfirmed completion. A recent cooldown is not a success or evidence that nothing changed. Successful entries link the exact recorded filing checkpoint, not today's filing. History is paged twenty at a time. The latest status is visible with history closed. Reads of the workspace, history and weekly review make no source or model calls; exports identify whether daily filing acquisition is enabled.

Verification: the integrated suite passed 630 checks with both retained real-data corpora. That includes six real-company saved-response replays through scheduled acquisition and unchanged-repeat checks; the schedules and timing are authored. Final focused verification adds the late-completion guard. Browser checks cover a visible failure, 22-entry history, source links, opt-in/stop presentation, missing identity and 320/390/1440px layouts. Browser toggle responses are mocked to prevent live HTTP; actual API, ownership and scheduler behavior are exercised by backend tests. No claim of prospective detection accuracy or participant value follows from these checks.
