# Financial performance — phase 14

Open a real company’s **Fundamentals** tab. **Annual financials** and **Latest quarter** independently select the newest retained 10-K and 10-Q, including amendments. The newer reporting end is selected initially; switching views does not change a saved condition. The view shows business performance, cash generation and balance-sheet components, with native expandable rows for explanations, exact inputs, comparisons and original SEC links.

## Calculation and period contract

Fifteen rows cover revenue, operating income, net income, revenue growth, operating margin, operating cash flow, cash payments for property/plant/equipment, an explicitly labelled free-cash-flow calculation, cash/equivalents, noncurrent long-term debt, its current portion, commercial paper, assets, liabilities and liabilities/assets. The existing tested growth/margin selector is reused. Other values come from whole-entity US-GAAP USD concepts in the exact selected accession/form/filing date. No additional data library, model or paid supplier is needed.

Income uses a directly reported 70–110-day quarter or 350–380-day annual period. Cash flow uses the longest compatible period ending at the selected report date: annual or 70–310 days for a quarterly filing, normally fiscal year to date. Exact dates are shown on every row. There is no subtraction of YTD/annual filings to infer a quarter. Cash-flow subtraction requires identical input dates. Instant balance-sheet inputs must match the report end. Comparisons are from the same filing: compatible prior-year duration for income/cash, or the latest earlier reported instant balance. A balance comparison is not necessarily a year earlier.

Free cash flow is operating cash flow less cash payments for property, plant and equipment. This is an app-defined non-GAAP calculation, excludes noncash additions and is not labelled cash freely available for spending. The [SEC’s discussion, question 102.07](https://www.sec.gov/rules-regulations/staff-guidance/corporation-finance-interpretations/non-gaap-financial-measures) explains why the definition and limitations matter. Liabilities/assets uses a positive asset denominator; it is not a debt ratio. Debt components are displayed separately, never summed into an incomplete total. Missing commercial paper is unknown; an explicitly reported zero remains zero.

Decimal arithmetic precedes display rounding. Conflicting values/periods, missing or foreign-currency inputs remain unavailable. Amendments without usable facts do not fall back to older filings. The selected revenue/margin ratios retain the existing bounded monitoring convention. Custom taxonomy, segments, currency conversion, total-debt normalization, rolling TTM and general valuation are not implemented here. The [SEC API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) supplies standard whole-entity facts; issuer-specific interpretation still requires the filing.

## Persistence and source access

Migration 014 adds immutable `performance_snapshots` plus `performance_current`. Each snapshot has the exact retained payload, normalized report data and method `sec-performance-1`. Successful SEC collection prepares it in the existing short collection transaction. A truncated response cannot remove or regress a retained annual/quarter report; the transaction rolls back and a normal refresh reports failure. Corrections append snapshots; A → B → A restores the original identity. Unchanged normalized data reuses it.

This display contract is separate from the two existing monitoring metrics. New cash or balance-sheet data alone does not invent a monitoring condition or issue a numerical alert. Existing condition definitions, source identities, old evaluations and private alert history remain unchanged. Opening/switching views performs no source or model request. Source withdrawal hides this financial panel; failed/stale checks label retained data. Older history/API source-withdrawal presentation remains a separately recorded audit concern.

After upgrading, **Refresh filings** prepares the new view. There is no blind backfill claiming an old bundle was newly retrieved. It uses the existing user-agent, global request clock, 15-minute cooldown and no automatic retry. No new API key is required. The browser can inspect current values; dedicated financial-snapshot export/history selection is not yet exposed.
